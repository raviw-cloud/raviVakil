# Professional Leave & License Agreement Review PDF Generator

You are the PDF report generator for `/leave-license-pdf`. When invoked, you locate the most recent Leave & License Agreement review analysis, then render a polished, client-facing PDF using the active generation pipeline.

## When This Skill Is Invoked

The user runs `/leave-license-pdf` after completing a Leave & License Agreement review via `/legal review` or similar analysis. Do not invoke this skill proactively.

---

## Phase 1: Locate Analysis Data

### 1.1 Find the Most Recent Review

Search the working directory for the most recent Leave & License Agreement review output file, in this order:

1. `LEAVE-LICENSE-REVIEW-*.md`
2. `L&L-REVIEW-*.md`
3. `AGREEMENT-REVIEW-*.md`
4. Any `.md` file containing "Leave and License", "License Agreement", or "L&L Agreement"

Use the Glob tool. If multiple matches exist, use the most recently modified file.

**If no analysis file is found:** Tell the user to run `/legal review <agreement>` first. Do NOT proceed.

### 1.2 Parse the Analysis Data

Extract the following from the analysis file:

| Data Point | Source |
|-----------|--------|
| Overall Risk Score (0–100) | "Risk Score: X/100" or "Overall Score: X" |
| Legal Grade (A–F) | "Grade: [letter]" |
| Risk Classification | "MEDIUM RISK" / "HIGH RISK" / "LOW RISK" |
| Agreement Type | "Leave & License Agreement" or "L&L Agreement" |
| Parties | Licensor name and Licensee name |
| Property Address | Full address of licensed premises |
| Execution Date | Date agreement was signed |
| Registration Details | Registration date and document number |
| Term / Duration | Start date, end date, total duration (e.g., 11 months) |
| Monthly Rent | Rent/license fee amount |
| Security Deposit | Deposit amount |
| Executive Summary | Overview paragraph of agreement analysis |
| Critical Risks | List of 3-4 most critical issues |
| High-Risk Issues | Additional high-priority risks |
| Medium-Risk Issues | Medium-priority concerns |
| Key Clauses Analysis | Clause name, position, risk level, legal comment (table format) |
| Missing Protections | List of absent critical clauses (dispute resolution, refund timeline, etc.) |
| Obligations | Table: Party, Responsibility, Due Date/Timing, Consequence of Breach |
| Recommended Actions | Prioritized amendments (P1 Critical, P2 High, P3 Medium) |
| Amendment Language | Proposed clause text for each recommended amendment |

## Phase 2: Generation Pipeline

The PDF is generated by the **pdfkit** route in `server.js` at `/api/download-leave-license/:sessionId`. This route reads pre-cached JSON analysis data and renders the document directly.

When invoking from the CLI skill context (outside the web app), generate inline using ReportLab:

```bash
pip3 install reportlab 2>/dev/null || pip install reportlab 2>/dev/null
```

All design specs below apply equally to both pipelines (pdfkit/server.js and ReportLab).

## Phase 5: Layout Anti-Patterns to Avoid

| Anti-Pattern | Why It Breaks | Fix |
|---|---|---|
| Text at y ≥ 792 | pdfkit auto-adds page; text lands on blank page | Keep all text at y < 792 |
| Dense paragraphs | Poor readability; intimidating legal document | Use cards, bullets, short blocks |
| Monochrome design | Flat, uninviting; hard to scan risk levels | Use RED/ORANGE/YELLOW/GREEN consistently |
| Missing section headers | Reader loses context across pages | Include section header on every major section |
| No visual hierarchy | All content appears equally important | Use font sizes, colors, borders, spacing intentionally |
| Tables without alternating rows | Hard to track row alignment | Alternate WHITE / BG-LIGHTER rows |
| Oversized metric cards | Wastes vertical space | Grid layout with 4 cards across; compact sizing |
| No page numbers | Reader loses place in long document | Include "Page N" in footer |

|-------|-----------|
| No agreement analysis file found | Tell user to run `/legal review <agreement>` first. Do NOT generate PDF. |
| Missing critical data fields | Use placeholder text (e.g., "[TBD: Risk Score]") and note in report footer that data is incomplete. |
| Party names or dates missing | Ask user for clarification via terminal before proceeding. |
| Risk score outside 0–100 range | Clamp to 0–100. Log warning. |
| Very long descriptions (>500 chars) | Truncate at word boundary + "...". Add full text in footnote if critical. |
| PDF rendering fails | Show error message with file path. Ask user to check pdfkit/ReportLab installation. |
| Metrics do not align to grid | Use fixed widths per design spec. Adjust padding/font size, not grid. |
