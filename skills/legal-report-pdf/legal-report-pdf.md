# Professional PDF Report Generator

You are the PDF report generator for `/legal report-pdf`. When invoked, you locate the most recent contract review analysis, then render a polished, client-facing PDF using the active generation pipeline.

## When This Skill Is Invoked

The user runs `/legal report-pdf` after completing a contract review via `/legal review`, `/legal freelancer`, or a similar command. Do not invoke this skill proactively.

---

## Phase 1: Locate Analysis Data

### 1.1 Find the Most Recent Review

Search the working directory for the most recent contract review output file, in this order:

1. `CONTRACT-REVIEW-*.md`
2. `FREELANCER-REVIEW-*.md`
3. `COMPLIANCE-AUDIT-*.md`
4. `NDA-REVIEW-*.md`
5. Any `.md` file containing "Contract Safety Score", "Freelancer Fairness Score", or "Compliance Scorecard"

Use the Glob tool. If multiple matches exist, use the most recently modified file.

**If no analysis file is found:** Tell the user to run `/legal review <file>` first. Do NOT proceed.

### 1.2 Parse the Analysis Data

Extract the following from the analysis file:

| Data Point | Source |
|-----------|--------|
| Score (0–100) | "Contract Safety Score: X/100" or "Overall: X%" |
| Grade | "Grade: [letter]" |
| Recommendation | SIGN / NEGOTIATE / AVOID / REJECT |
| Contract type | "Contract Type" row |
| Parties | "Parties", "Hiring Party", or "Freelancer" rows |
| Effective date | From filename or "Effective Date" |
| Risk dashboard | High / Medium / Low counts + clause names |
| Clause analysis | Name, risk level, summary, recommendation per clause |
| Missing protections | "Missing Protections" or "Freelancer Bill of Rights" section |
| Obligations | "Obligations & Deadlines" table |
| Compliance flags | "Compliance Flags" section |
| Recommendations | Numbered list with priority tags |
| Executive summary | "Executive Summary" section |

---

## Phase 2: Generation Pipeline

The PDF is generated by the **pdfkit** route in `server.js` at `/api/download/:sessionId`. This route reads pre-cached JSON analysis data and renders the document directly — it does **not** call Python or ReportLab.

When invoking from the CLI skill context (outside the web app), generate inline using ReportLab:

```bash
pip3 install reportlab 2>/dev/null || pip install reportlab 2>/dev/null
```

All design specs below apply equally to both pipelines.

---

## Phase 3: Design System

### 3.1 Design Tokens

| Token | Value | Usage |
|-------|-------|-------|
| SLATE | `#1E293B` | Primary text, header bars, table headers |
| BLUE | `#2563EB` | Accent lines, section bars, NOTE callouts |
| WHITE | `#FFFFFF` | Page background, table header text |
| LIGHTBG | `#F3F4F6` | Score panel fill, alt-row base |
| ALTROW | `#F8FAFC` | Alternating table rows |
| RED | `#DC2626` | HIGH risk, WARNING callouts, reject verdict |
| AMBER | `#D97706` | MEDIUM risk, NEGOTIATE verdict |
| GREEN | `#16A34A` | LOW risk, SIGN verdict, TIP callouts |
| GREY | `#6B7280` | Muted text, footers, separators |
| Font | Helvetica (built-in) | Body 10–11pt; bold variant for headings |
| Size hierarchy | 26 / 18 / 10–11 / 8–9pt | Title / section / body / captions |

### 3.2 Page Setup

| Property | Value |
|----------|-------|
| Page size | A4 (595 × 842pt) |
| Margin | 50pt all sides |
| Safe text zone | y < 792 (= 842 − 50). **Never place text at y ≥ 792** — pdfkit auto-adds a page at that boundary, creating blank pages. |
| Content width (W) | 495pt |
| Content top (CTOP) | 88pt (below page header bar) |
| Content bottom (CBOT) | 760pt (above footer) |

## Phase 4: Page-by-Page Layout Specification

### 4.1 Cover Page

The cover is a single self-contained page. All text must be placed at y < 792. Draw shapes at any y; only text triggers the auto-page boundary.

#### Top band (y = 0–185)
- Full-width SLATE rectangle
- 4pt BLUE accent line at y = 185
- Title "CONTRACT REVIEW REPORT" — WHITE, 26pt bold, centered, y ≈ 62
- Subtitle "AI-Powered Neutral Legal Analysis" — LIGHTBG, 12pt, centered, y ≈ 102
- Date — LIGHTBG, 9pt, centered, y ≈ 128

#### Score Panel (y = 208, height = 124, full-width rounded rect, fill LIGHTBG)

The score panel is **horizontal**, not a circle. It has three zones separated by thin vertical rules:

**Left zone (x = 62–166):**
- Large score number — 54pt, colored by grade (RED/AMBER/GREEN), centered
- "/ 100" label — GREY, 8pt, centered below

**Centre zone (x = 202–284):**
- Grade letter — 40pt, colored by grade, centered
- Grade label (Excellent / Good / Satisfactory / Fair / Below Average / Poor / Critical Risk) — GREY, 8pt, centered below

**Right zone (x = 308–528, rounded rect, fill = verdict color):**
- "VERDICT" label — WHITE, 9pt, centered
- Verdict word (SIGN / NEGOTIATE / AVOID / REJECT) — WHITE, 20pt bold, centered

#### Risk Count Row (y ≈ 354, three rounded rects, each 150 × 56pt)
- Left: HIGH RISK count — RED fill
- Centre: MEDIUM RISK count — AMBER fill
- Right: LOW RISK count — GREEN fill
- Count number: 24pt WHITE bold; label: 7pt WHITE

#### Summary Snippet (y ≈ 432)
- First 240 characters of the executive summary — GREY, 9pt italic, justified
- Followed by a thin LIGHTBG separator line

#### Document Metadata (below snippet)
- "Document" label (SLATE bold) + filename (GREY) on one line
- "Review Type" label + "Neutral Legal Analysis — AI Legal Assistant" on next line
- Both at 8pt

#### Bottom Band (y = 630–842, SLATE fill, 3pt BLUE top accent)
- "AI Legal Assistant" — LIGHTBG, 9pt, centered at **y = 656** (safe)
- Disclaimer — GREY, 7pt, centered at **y = 674** (safe)

> After all cover drawing is done, set `cover = false` before the first `addPage()` call for content pages.

---

### 4.2 Page Header and Footer (All Non-Cover Pages)

Rendered via the `pageAdded` event handler.

**Header bar (y = 0–51):**
- SLATE rectangle, 48pt tall
- 3pt BLUE line at y = 48
- "CONTRACT REVIEW REPORT" — WHITE, 9pt, left-aligned at y = 18
- "AI Legal Assistant" — WHITE, 9pt, right-aligned at y = 18

**Footer (y = CBOT + 5 to CBOT + 25):**
- 0.5pt GREY separator line at y = CBOT + 5
- Left: "AI Legal Assistant — Contract Review" — GREY, 7pt
- Centre: "CONFIDENTIAL" — GREY, 7pt
- Right: "Page N" — GREY, 7pt (increment a `pageNum` counter in the handler)

After rendering header and footer, reset `doc.y = CTOP` (88).

---

### 4.3 Section Header (`secHdr`)

Every major section calls `secHdr(title)`, which adds a new page and renders:

- 4pt BLUE vertical bar at x = 50, y = 60, height = 26
- Section title — SLATE, 18pt bold, starting at x = 62, y = 60
- 0.5pt BLUE horizontal rule at y = 88 (same as CTOP)
- Set `doc.y = CTOP` (88)

Do **not** redraw a full navy band across the top of the page — the page header from `pageAdded` already handles this. The `secHdr` accent bar sits in the white area below the header strip.

---

### 4.4 Executive Summary

Renders on its own page via `secHdr('Executive Summary')`.

1. Summary paragraph — SLATE, 10.5pt, justified, `lineGap: 3`
2. Risk count boxes — three rounded rects (150 × 58pt each) in RED / AMBER / GREEN
3. **Critical Issues inline list** — if space remains (doc.y < CBOT − 80), render the top HIGH-severity risks as compact entries:
   - 3pt RED left bar
   - Risk title — SLATE, 9pt bold
   - Short explanation (≤ 120 chars) — GREY, 8pt
   This prevents the lower half of the page from being blank.

---

### 4.5 Tables (`drawTable`)

Used for Key Clauses, Risk Assessment, Obligations & Deadlines.

| Element | Spec |
|---------|------|
| Header row | SLATE fill, WHITE 8pt bold text |
| Odd rows | ALTROW (`#F8FAFC`) fill |
| Even rows | WHITE fill |
| Row height | Min 22pt; auto-expands for long text |
| Body text | SLATE 8pt; HIGH/MEDIUM/LOW colored by severity |
| Overflow | On page break, re-render header row on new page; set `doc.y = CTOP` |

No outer table border — the fill rows provide sufficient visual structure.

---

### 4.6 Callout Blocks (`drawCallout`)

Used for Compliance Flags. Each flag is a callout block with:

- Background tint + 4pt colored left border
- Bold type label (WARNING / NOTE / TIP) in border color
- Body text — SLATE, 9pt

Color mapping:

| Type | Border | Background |
|------|--------|------------|
| WARNING | RED `#DC2626` | `#FEF2F2` |
| NOTE | BLUE `#2563EB` | `#EFF6FF` |
| TIP | GREEN `#16A34A` | `#F0FDF4` |

Callout height is calculated dynamically using `doc.heightOfString(text, { width: W − 24 }) + 28`.

---

### 4.7 Recommendations

Rendered after Compliance Flags.

Each recommendation has:
- Priority badge (26 × 15pt rounded rect): P0 = RED, P1 = orange `#E64A19`, P2 = AMBER, P3 = GREEN, P4 = indigo `#5C6BC0`
- Recommendation text — SLATE, 9.5pt, starting at x = 82

Priority P0 is placed first. Items are compact (no separators) to avoid a sparsely populated page.

## Phase 5: Layout Anti-Patterns to Avoid

| Anti-Pattern | Why It Breaks | Fix |
|---|---|---|
| Text at y ≥ 792 | pdfkit triggers auto-addPage; text lands on blank page; cover flag may be wrong | Keep all explicit-y text at y < 792 |
| Bottom band text at y > 792 | Creates blank pages 2–3 before any content | Start bottom band at y ≤ 640; draw text at y ≤ 680 |
| Full-width colored bar in secHdr | Overpaints page header; double-renders on new page | Use left accent bar + underline rule instead |
| Isolated score circle in large white space | Looks primitive, wastes vertical space | Use horizontal score panel with grade + verdict zones |
| Section occupies entire page for 2–3 items | Half-page blank after sparse content | Append next logical content block to fill the page |
| Re-declaring `var sc`, `var recC` in two places | Runtime shadowing bugs | Declare once at top of the PDF route handler |

## Phase 6: Error Handling

| Error | Resolution |
|-------|-----------|
| No analysis file found | Tell user to run `/legal review` first |
| ReportLab not installed (CLI path) | Run `pip3 install reportlab` and retry |
| Analysis file unreadable | Report error; ask user to verify the file |
| PDF generation fails | Show error, attempt fix, retry once |
| Python not available (CLI path) | Report that Python 3 is required |

## Phase 7: Delivery

After generating the PDF:

2. State the absolute file path
3. List sections included and estimated page count
4. Note any sections skipped due to missing source data
